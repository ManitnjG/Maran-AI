# MARAN Privacy Policy Draft

_Last updated: 8 October 2026_

This document is the privacy-policy draft for the Google Play distribution of MARAN. Add a public support contact and publish this document at a stable public URL before Play submission.

## What the Play build accesses

MARAN may request microphone access when the user starts voice recognition. MARAN uses Android's speech-recognition flow and receives the recognized text. The speech-recognition provider selected on the device may process audio under that provider's own terms.

MARAN may request camera permission only to control the device flashlight. MARAN does not use that permission to take or retain photos or video.

The Google Play build does **not** request broad Contacts permission. When a named-contact calling action is requested, MARAN opens Android's system contact picker so the user chooses the phone number. MARAN then opens the system dialer; the user decides whether to place the call.

The Google Play build does **not** include an AccessibilityService and does not request broad launcher-app inventory visibility.

## AI chat and mission data

When the user sends a general AI chat request, the text needed for that request and recent non-local chat context may be transmitted to the configured AI provider. MARAN currently supports OpenRouter in the Android chat experience and configurable providers on the MARAN server.

Local Android tool results are marked local-only and are excluded from later cloud-AI context. This includes local device-control outcomes and local device information generated by supported on-device tools.

When the user creates a remote MARAN mission, mission text, worker outputs, verification data, learned workflow metadata, user-created workspace memory, and reviewed action metadata may be stored on the configured MARAN backend. Workspace memory is intended for non-secret preferences and rejects obvious credential-like values.

Users may explicitly upload PDF, DOCX, TXT, Markdown, CSV or JSON files as MARAN Knowledge Files. Each upload has a separate "Allow AI context" choice. Only matching snippets from files the user explicitly allows can be inserted into AI worker prompts. Files not allowed for AI context remain searchable on the configured MARAN backend but are not automatically added to AI prompts.

## Credentials

OpenRouter keys and MARAN server access tokens saved in the Android app are stored using Android Keystore-backed local encryption. They are not intentionally placed in AI prompts or mission exports.

## External integrations

If the operator connects services such as Gmail, Google Calendar, Google Drive, GitHub, WhatsApp, social platforms, Twilio, or Tally to the MARAN backend, data is sent to those services only when the corresponding feature is used. Consequential write actions remain confirmation-gated in Approval Centre. Approval applies to the displayed action and arguments; it does not grant a general permission for future actions.

## Data MARAN does not request in the Play build

The Play build does not request SMS or call-log permissions, location permissions, broad Contacts permission, AccessibilityService access, or QUERY_ALL_PACKAGES. It does not bypass CAPTCHA, OTP, passwords, PINs, biometrics, payment authentication, Android security controls, queues, or anti-bot systems.

## Advertising and sale of data

MARAN does not include an advertising SDK in the current project and does not sell user data.

## Retention and deletion

Clearing MARAN AI chat removes the current in-app chat history. Uninstalling the app removes app-local settings and encrypted local credentials subject to Android platform behavior. Workspace-memory items and Knowledge Files can be deleted individually in MARAN. The app also provides a confirmed "Delete remote MARAN data" control that deletes the default workspace's remote missions, workspace memory, learned workflows, Knowledge Files and built-in CRM leads. It does not delete data already stored by external services such as Gmail, Drive, Calendar, GitHub, social platforms or Tally.

## Security

Production Play builds reject cleartext HTTP backend configuration and require HTTPS. Sensitive Android permissions are minimized and requested only when a user invokes the related feature. Notification permission, where required by Android, is optional and is used for mission approval, completion, blocked or failed status alerts.
